# 修订与实际交付

## 先界定修改与保护内容

读取现稿、有效反馈和相关资源。分清哪些意见替换旧要求，哪些只是局部调整；明确需保持的事实、能力、源材料、用户输入和协作资源。修订后按完整新成稿思考，而不是把每条反馈追加成一段解释。

默认更新目标文档，不另存旧版；清除正文中的编辑对话、修改理由、删除线和 diff。若需要说明变化，单独给简短摘要。研究对象的 diff、受托保留的讨论记录、学习者原始回答、红线稿、批注和版本历史属于用途明确的例外，不能按“过程信息”一律删除。

关键内容变化后检查依赖：数字与摘要/图表，结论与建议，人物选择与后续场景，素材与执行卡，当前实例与长期模板，本地源稿与发布稿。仅更新确实受影响的内容，不因全篇思考而机械重写整个对象。

精简、合并或跨期继承行动记录时，核对是否丢失协作对象、前置条件、期限、入口及尚未完成的子事项；完成或取消状态不能只由父项勾选、空白复选框或旧日期推断。将保留下来的条件与新稿逐项对照，再从读者视角走查能否开始处理、能否分别确认完成；格式和链接数量不能代替这一步。

## 结合载体完成验收

有对应格式或平台技能时使用它，复用已明确的读者、材料和结构，不让用户重复提供信息或确认提纲。专业技能负责具体文件结构、工具操作、渲染和平台约束；本 Skill 不覆盖其必要检查，也不自行扩大外部发布权限。

| 载体 | 实际检查 |
| --- | --- |
| 本地文本、Markdown | 回读当前文件；核对正文完整性、链接与资源路径、代码块或表格是否破坏阅读；涉及相对路径时从实际使用位置检查 |
| Word | 默认干净稿接受全部修订、删除批注；明确要求保留时按任务处理。重开并渲染检查实际页面、正文、表格和资源，不能只检查 XML 或隐藏标记 |
| PDF | 打开并按适用技能渲染检查页面，注意溢出、缺字、图表和页间关系；可提取文字不等于页面可读 |
| Notebook | 检查单元类型、顺序、链接与资源、原始回答和应保留输出；按任务验证阅读与执行。JSON 可解析不等于学习内容完整，离线通过不等于真实服务调用成功 |
| 飞书及在线文档 | 写前读取最新正文、版本和资源，按安全范围修改；写后回读目标位置、关键内容与资源。保留未授权删除的协作评论、附件及历史；链接存在不等于目标用户有访问权限 |
| HTML 与交互审阅材料 | 用实际页面检查阅读路径、资源、导航、正文版本和评论定位；写作任务使用现有交互能力，不为通过文档检查擅自改造产品 |
| 演示稿、表格及多载体交付 | 按专门技能检查计算、页序、可编辑内容及呈现；源稿与各派生稿分别核对，同一内容不能在不同载体互相矛盾 |

验收力度随产物和风险选择，但应覆盖用户真正收到的东西。平台采用局部替换可以形成完整干净稿，不必重建对象；格式转换后要检查转换本身引入的问题。

## 处理未完成与交付说明

环境或权限阻断时，保留已完成的可用产物，说明受影响部分及判断限制；不要拿本地镜像冒充线上成功。Agent 造成的错误格式、遗漏、损坏或未回读需要修复，不能一律排除为技术失败。

最终给出可访问的产物，简要说明完成内容和实际验证范围；需要用户判断的事项提供具体事实和选择。按已有授权执行所需写入或发布，不重新索要已经获得的许可，也不把写作授权扩大为发送消息、公开发布或修改全局配置。
