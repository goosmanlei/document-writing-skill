# Agent 文档与文档集合

服务于未来任务恢复、判断和执行，不能依赖当次聊天才知道的省略前提。详细程度由必要条件决定，不把所有历史复制进长期指令。

## 先确认现有分工

读取相关入口及当前规则，确认哪些材料分别承担导航、长期约束、已确认知识、当前状态、执行步骤和历史证据。沿用合理分工，不为套命名模板强制新增文件。

同一事实或规则尽量有明确的维护位置，其他入口用引用衔接。必要重复应清楚哪些内容需同步；当前实例与长期模板承担不同用途，任务要求两者变化时都要处理。

遇到相互矛盾的流程、路径或状态，根据有效用户要求、适用范围、已确认决定与实际版本解决。最新文件不自动最权威；依据不足时给出冲突事实、影响和需决定的问题，不能直接挑一个。文档声称的计划、配置中的设置和实际执行结果分开核验。

## 保留执行与恢复能力

规则需说明适用条件和例外；步骤保留必要入口、路径、命令、参数、前提及结果判据。精简前辨认它们承担的作用，不能因它们看起来细碎就删掉。

临时决定只在适用范围内保存。若要转为长期规则，应写清独立成立的理由和边界；没有依据时不要从当前目录名或单次约定推导全局要求。状态文档保留当前有效进度、待定与下一步；知识文档只沉淀已确认、可复用的事实。

交接应让新 Agent 找到当前任务、有效材料和继续工作入口。不要把待决定项仅记成一个不透明引用；供人决策时给足事实、影响和选项。也不要把未完成工作记成已验证结论。

迁移工作方式时确认哪些旧调度、规则或入口被替代，哪些资料仍有价值。停止某种工作方式不等于删除所有旧成果；更新文档不等于运行配置已经改变。

## 集合审阅

模拟一个没有旧聊天的新 Agent：能否找到当前依据并开始任务，路径和命令是否适用，多个入口是否一致？再检查修订是否误删有效能力、保留了无效状态或把当前反馈扩大成无关约束。发现问题修正文档及实际受影响的引用，不扩展成未授权的项目重构。
