# 文档创作

让读者凭交付物完成其理解、判断、执行、学习或体验的目的。按任务决定详略和结构：面向人不等于越短越好，面向 Agent 不等于堆入全部历史。普通即时问答无需展开完整文档流程。

## 明确任务，再选择方法

从已有上下文确定读者及其基础、读后任务、全部有效要求、材料与版本、交付位置、保护内容和完成条件。修订先读现稿；多份文档共同工作时先确认入口和职责。局部反馈只改变对应部分，其他目标继续有效。

能从上下文合理判断时自主推进；只有缺失信息会显著改变方向、范围或正确性时才问，同时继续不依赖答案的工作。不因写作擅改业务规则、运行系统或用户选择的载体。

按实际用途读取必要参考，可以组合，不必全读：

- 分析、研究、决策、操作说明、工作安排、技术解释、学习、翻译、记录或管理沟通：读 [论证与说明](references/analysis-and-explanation.md)。
- 故事、小说、剧本、创作方向、地图或视听制作材料：读 [创作与叙事](references/creative-writing.md)。
- AGENTS、SKILL、README、状态或交接文档：读 [Agent 文档与文档集合](references/agent-documents.md)。
- 修订、保护区、多版本、跨载体或文件与平台交付：读 [修订与交付](references/revision-and-delivery.md)。

## 自主递进创作

以下是内容依赖，不是固定调用次数、文件数量或逐阶段审批。按复杂度调整粒度，不强制保存底稿或展示中间过程。

1. **确定目的与材料。** 回查整个任务，区分阶段产物与最终目标。核对关键材料的适用时点、来源和缺口，版本或时点不明时不把推测写成事实。
2. **先形成内容关系。** 已有研究结果时先拟结论，再逐项建立理由和证据；研究尚未完成时从问题与证据形成可修改的判断，不能先锁结论再挑材料。操作文档理清条件、动作与结果，技术说明理清对象与时序，叙事形成足以支持当前写作的人物选择、冲突和场景关系。骨架不只是空标题；创作也可通过试写继续发现内容。
3. **展开并检验整体。** 按读者阅读、行动或体验顺序成稿。关键事实或内容关系不成立就返回上游，不以句子润色掩盖逻辑缺口。局部完成后通读全文；修改数字、结论、人物或动作时检查关联摘要、图表、后文和派生产物。
4. **审阅实际成稿。** 先只凭正文检查读者能否理解和使用，再结合来源核验事实、推断、归属和保护要求。先修目的、事实和结构，再修措辞。复杂论证、长篇或多文档任务可增加独立审阅，不把每个短任务变成多轮评审。
5. **验收交付。** 用适用的文件或平台技能完成写入、渲染及资源检查，复用前面的任务判断。回读用户实际收到的版本，修复转换和更新引入的问题；只声称实际验证过的范围。

## 成稿必须守住的边界

- **结论与依据相称。** 关键事实、数字和判断有可追溯支撑；引用本身不能替代论证。区分事实、他人观点、推断、假设、建议与已确认决定，用自然措辞表达，不必逐句贴标签。反证或来源冲突应改变结论或其范围。虚构按原作要求和作品设定检查，真实背景另行核实。
- **精简不丢理解与行动条件。** 首次使用读者不熟悉的概念时解释含义和用途；保留必要背景、因果、例子和入口。关键发现讲清依据及意义；图表和标题与正文共同回答相关问题。允许叙事按悬念安排信息，不把解释性要求变成剧透或作者说教。
- **修订后独立成立。** 默认直接更新目标文档，交付完整干净稿，不另存旧版，不把修订讨论、修改理由或 diff 混入正文。用户明确要求的讨论记录、研究对象 diff、学习者原始回答、红线稿、批注或版本保留继续有效。必要修改摘要另给。
- **文档集合保持一致。** 规则、状态、历史和操作材料各司其职。冲突按有效要求及可核实版本解决，不能只凭文件名或新旧猜测；同步确实受影响的入口、模板和实例，保留仍有效的资料与执行能力。
- **内容完成与交付可用分别核验。** 写入提示、元数据通过或模型说“已审阅”都不是成品验收。文件需检查实际正文、资源和呈现；在线更新保护协作资源并写后回读。环境阻断与 Agent 导致的缺陷分开处理，不把后者用“技术问题”一笔带过。

## 读者视角的最后一遍

拿实际成稿回答与用途相关的问题：读者能否复述核心意思、说明理由及条件、作出所需判断或完成动作？故事中的人物选择、场面、空间、节奏与照应是否成立？有没有需要作者补充聊天背景才能理解的地方？有没有漏掉原任务、破坏保护内容或让其他文档失效？

理解审阅不能靠额外解释补救，事实核验也不能只靠正文自证。独立 Agent 是读者代理，不能冒充真实用户已认可或已完成操作。存在未验证项时简明说明其影响，同时给出可访问的实际产物。日常写作不运行本项目的长期评测，也不增加默认审批。
